# 1. Purpose

The Change Log records significant project changes, milestones, enhancements, fixes and documentation updates throughout the lifecycle of the QuickBite project.

Unlike Git commit history, this document provides a high-level summary of meaningful engineering and product changes that affect the project.

Its purpose is to provide complete project evolution traceability across all Software Development Life Cycle (SDLC) phases.

---

# 2. Scope

This document records changes related to:

- Product Vision
- Business Requirements
- Functional Requirements
- Architecture
- Engineering Standards
- Documentation
- Development
- Testing
- Deployment
- Production Releases

Minor editorial changes, spelling corrections and formatting updates shall not be recorded.

---

# 3. Versioning Strategy

QuickBite follows Semantic Versioning (SemVer).

```
MAJOR.MINOR.PATCH
```

### Version Components

| Component | Description |
|------------|-------------|
| MAJOR | Breaking architectural or product changes |
| MINOR | New features, modules or major documentation milestones |
| PATCH | Bug fixes, corrections and minor improvements |

Example:

| Version | Meaning |
|----------|---------|
| v0.1.0 | Initial Project Setup |
| v0.5.0 | Major Requirement Engineering Progress |
| v1.0.0 | Initial Production Release |
| v1.2.0 | New Feature Release |
| v2.0.0 | Major Platform Evolution |

---

# 4. Change Categories

All project changes shall be classified using the following categories.

| Category | Description |
|----------|-------------|
| Added | New features, modules or documents introduced |
| Changed | Existing functionality or documentation modified |
| Improved | Performance, quality or maintainability enhancements |
| Fixed | Defects or inconsistencies resolved |
| Deprecated | Features scheduled for removal |
| Removed | Features permanently removed |
| Security | Security-related improvements |
| Documentation | Documentation additions or updates |

# 6. Release Management Policy

The following rules apply to project releases:

- Every major milestone shall receive a version identifier.
- Every released version shall include a summary of significant changes.
- Version history shall remain immutable.
- Historical versions shall never be modified.
- New releases shall always be appended.

This document shall be updated whenever:

Each new version shall be appended to the Version History.

Existing release records shall never be deleted or modified to preserve complete project history.
